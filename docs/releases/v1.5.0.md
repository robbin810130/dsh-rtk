# dsh-rtk v1.5.0 — `/rtk doctor` 与 `/rtk gain`

v1.4.0 的 `/rtk` 只回答"生效没有"。这一版把它补成完整的会话内自检面：

- `/rtk doctor`：完整自检（二进制、各 profile 安装版本、运行中的宿主进程、状态记录），
  与 `npm run doctor` **共用同一个 `runDoctor()`**，两条路径不可能给出不一致的结论。
  区别只是它使用插件自己进程内的解析结果，并把来源标注为「插件进程内解析」。
- `/rtk gain [summary|daily|weekly|monthly|history|project|json]`：读取 RTK 节省统计。
  用户输入映射到固定的只读参数，**不转发原始文本**——避免误触 `rtk gain --reset` 这类
  会清空统计的开关。输出超过 40 行会截断并提示到终端查看完整版。
- 重构：自检逻辑从 `scripts/doctor.mjs` 抽到 `dsh-rtk/lib/doctor.js`（并随包发布），
  CLI 变成薄壳；`runDoctor()` 的输入（环境、平台、宿主列表、profile 列表、状态记录、
  解析结果）全部可注入，测试无需触碰真实机器。
- 运行时新增 `run(subcommand, args)`，用于以已解析的二进制执行只读子命令。
- 测试：`/rtk` 四种输入 + `gain` 白名单拒绝 + `doctor` 复用报告文本；其余用例保持。
- 文档：README 的自检对照表扩到四项，新增 `/rtk gain` 输出示例与设计约定；
  Windows 说明补充子命令表。
